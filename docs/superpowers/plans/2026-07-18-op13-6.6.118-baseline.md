# OP13 6.6.118 Baseline Build Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` to implement this plan task-by-task.

**Goal:** Produce and verify a clean, unmodified `sun` 4K kernel image from the historical crDroid OnePlus 13 source at Linux 6.6.118, without attempting a flashable OxygenOS package.

**Architecture:** A small tracked Bash harness will keep the source checkout and output under an ignored, repository-local workspace. It will pin the source commit, validate the source version before any build work, invoke the kernel's supported `sun` build configuration with its pinned Android Clang toolchain, then write a manifest with hashes and release string. The build is a baseline-only checkpoint; it deliberately does not use KernelSU, ReSukiSU, SUSFS, OTA repacking, `fastboot`, or `adb`.

**Tech Stack:** Bash, Git, GNU Make, Android Clang `r510928`, Android kernel build scripts/Kleaf, `file`, `sha256sum`, `strings`.

## Guardrails

- Target device context is CPH2653 Global, OxygenOS `16.0.9.401(EX01)`; extracted stock KMI is `6.6.118-android15-8-g2e6b9c3812c5-ab15114928-4k`.
- The reproducible source checkpoint is `crdroidandroid/android_kernel_oneplus_sm8750` commit `d7067f0ef3dd7c9a48818c80f9cc4e34920e4f83`. Its `Makefile` declares `6.6.118`.
- This is an AOSP/crDroid baseline, not OnePlus's exact unpublished `g2e6b9c3812c5` source. A successful compilation is **not** evidence that the image is flash-safe on stock OxygenOS.
- All fetched sources, toolchains, build outputs, logs, and generated manifests stay under `.op13-baseline/` and must be ignored by Git.
- No partition is modified and no phone command is run in this phase.

## Task 1: Establish a local-only workspace and source identity contract

**Files:**
- Modify: `.gitignore`
- Create: `scripts/op13-baseline-build.sh`
- Create: `tests/op13-baseline-build-test.sh`

1. Add `.op13-baseline/` to `.gitignore`; do not ignore the user's existing OTA artifacts globally.
2. Create `scripts/op13-baseline-build.sh` with `set -euo pipefail`, a repository-root resolver, and these constants:
   - remote: `https://github.com/crdroidandroid/android_kernel_oneplus_sm8750.git`
   - commit: `d7067f0ef3dd7c9a48818c80f9cc4e34920e4f83`
   - expected source version: `6.6.118`
   - workspace default: `${OP13_BASELINE_WORKDIR:-<repo>/.op13-baseline}`
3. Implement a `verify-source` action that fails unless the source is at the pinned commit and `Makefile` contains `VERSION = 6`, `PATCHLEVEL = 6`, and `SUBLEVEL = 118`.
4. Implement a `fetch-source` action that clones only into `${workspace}/source`, checks out the pinned detached commit, then calls `verify-source`. It must refuse a non-empty incompatible source directory rather than silently resetting it.
5. Add a shell test that creates tiny disposable fake sources and proves `verify-source` accepts 6.6.118 but rejects 6.6.117 and a different Git revision. The test must not need network or a compiler.
6. Run: `bash tests/op13-baseline-build-test.sh`.
7. Commit the completed task: `chore: add OP13 baseline source guard`.

## Task 2: Pin the build dependencies and make the build action explicit

**Files:**
- Modify: `scripts/op13-baseline-build.sh`
- Modify: `tests/op13-baseline-build-test.sh`
- Create: `docs/op13-6.6.118-baseline-build.md`

1. Add a preflight action that checks for `git`, `make`, `bc`, `bison`, `flex`, `openssl`, `perl`, `python3`, `pahole`, `file`, `sha256sum`, and enough disk space; print exact missing packages/commands and exit non-zero before cloning or building.
2. Define a pinned, repository-local Android Clang `r510928` toolchain acquisition path. Use the revision referenced by this repository's OnePlus 13 manifest; record its URL and revision in the script, and validate that the expected `clang-r510928` executable exists before building.
3. Add a `build` action which first runs `verify-source`, uses only the fetched source and pinned toolchain, and invokes the source's `sun` / 4K build configuration. Preserve the full command in a timestamped log under `${workspace}/logs/`; do not use a generic GKI-only configuration as a substitute for the device target.
4. Fail clearly if the vendor build framework required by that source checkout is missing; document the exact fetch/bootstrap command rather than inserting guessed flags.
5. Extend the shell test to cover preflight reporting for a deliberately missing command and the refusal to build after a failed source check.
6. In `docs/op13-6.6.118-baseline-build.md`, state the exact target, source commit, toolchain revision, workspace path, expected output path, and the hard no-flash restriction.
7. Run: `bash tests/op13-baseline-build-test.sh`.
8. Commit the completed task: `build: add reproducible OP13 baseline harness`.

## Task 3: Record and verify a real clean baseline build

**Files:**
- Generated only: `.op13-baseline/source/`, `.op13-baseline/toolchains/`, `.op13-baseline/out/`, `.op13-baseline/logs/`, `.op13-baseline/results/`
- Modify if required by an observed source API mismatch only: `scripts/op13-baseline-build.sh`, `tests/op13-baseline-build-test.sh`, `docs/op13-6.6.118-baseline-build.md`

1. Install only the missing host prerequisite(s) identified by `preflight` (currently `bc` is absent); do not upgrade unrelated host packages.
2. Run `scripts/op13-baseline-build.sh preflight`, then `fetch-source`, then `build` in a clean `.op13-baseline/` workspace.
3. On success, have the harness write a result manifest containing source remote, exact commit, `Makefile` version, toolchain identity, full build command/log path, output path, `sha256sum`, `file` output, and the `Linux version` line extracted from the produced image.
4. Verify the output is non-empty, is an ARM64 kernel image, and its embedded release begins with `6.6.118`. Store no claim of stock-OOS compatibility in that manifest.
5. If the vendor build fails, stop at the first deterministic failure, retain the log, and fix only the documented harness/bootstrap mismatch. Do not switch sources, apply root patches, or relax the source/version guard to obtain a green build.
6. Re-run `bash tests/op13-baseline-build-test.sh` after any harness change.
7. Commit only tracked script/test/document changes: `build: verify OP13 6.6.118 baseline`; generated build artifacts remain untracked and ignored.
