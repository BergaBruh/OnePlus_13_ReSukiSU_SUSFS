# OP13 Global OOS16 6.6.118 GitHub Actions Build Design

## Goal

Provide a manual GitHub Actions build that produces a flashable kernel package for
the OnePlus 13 Global (`CPH2653`) on OxygenOS `16.0.9.401(EX01)`, with
ReSukiSU and SUSFS.  It must build only this target and must not enter the
repository-wide device matrix.

## Fixed Inputs

| Component | Repository | Revision |
| --- | --- | --- |
| OOS common kernel | `OnePlusOSS/android_kernel_common_oneplus_sm8750` | `e1b346b6b4f4096eb342ae3684838a942fd6f6c4` |
| OOS modules and device tree | `OnePlusOSS/android_kernel_modules_and_devicetree_oneplus_sm8750` | `d50b305f7da9e14715a25120a4ac7b1a4b8b97c3` |
| AnyKernel3 | `huangdihd/AnyKernel3` | `ea531d03965f702a45e1b0ab7c5db8d196c975c3` |
| ReSukiSU | `ReSukiSU/ReSukiSU` | `b0b73beb24341b7029a866005e9578ab58aa2df7` |
| SUSFS | `simonpunk/susfs4ksu` | `069baca65e58557019dbf906e802f518428c5a84` |

The pinned OnePlus common source declares Linux `6.6.118`.  The stock phone's
reported KMI remains the acceptance boundary: `6.6.118-android15-8-g2e6b9c3812c5-ab15114928-4k`.

## Design

- Add an OP13-Global-specific JSON config and manifest.  The manifest references
  full Git commit IDs for every fetched kernel/package input.
- Set `custom_patches` to `false` for this target.  This keeps the build to
  ReSukiSU and SUSFS rather than silently applying unrelated WildKernels
  performance, overlay, USB, or config-spoofing patches.  Existing configs
  preserve their current behavior through a `true` default.
- Add a dedicated `workflow_dispatch` workflow containing one `ubuntu-latest`
  job.  It checks out this repository, installs the dependencies required by the
  existing composite action, and invokes that action once with the fixed config
  and the fixed ReSukiSU/SUSFS commits.
- Keep the shared matrix workflow unchanged.  The dedicated workflow creates no
  GitHub release and handles no model other than `OP13`.
- Update the ReSukiSU setup-script URL in the existing composite action to use
  the supplied ref when one is provided.  Passing a SHA will then pin both the
  setup script and the ReSukiSU source, rather than fetching a moving script from
  `main`.

## Safety and Verification

- The workflow is manual-only.  It does not flash a device or alter boot images.
- A repository test validates the config, manifest pins, workflow scope, and the
  setup-script pinning rule before publication.
- The GitHub job must finish successfully and upload its AnyKernel ZIP artifact
  before it is considered a successful build.  A successful compile alone does
  not prove it is safe to flash; that still requires backup and device-side
  verification by the owner.
